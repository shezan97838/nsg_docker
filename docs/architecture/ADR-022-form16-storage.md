# ADR-022: Form 16 (income tax certificate) storage and access

Status: Accepted (2026-11-06). Migration `Add_Personnel_Form16` is NOT applied to any database.

## Context
The Salary Management admin uploads each person's Form 16 for an assessment year as two independent PDFs (Part A, Part B). The mobile app lets the signed-in person read their own. No external storage may be used.

## Decisions
1. **Table `personnel_form16`:** one row per (`nsg_number`, `assessment_year`), unique index `ix_personnel_form16_nsg_number_assessment_year`. `part_a_file_path` / `part_b_file_path` hold **relative** paths and are null until that part is uploaded. Timestamp columns are `*_ist` (`part_a_uploaded_at_ist`, `part_b_uploaded_at_ist`, `created_at_ist`, `updated_at_ist`) as the project's IST rule requires; the brief's `*_at` names were adapted. `uploaded_by` is the admin profile id of the latest upload. `nsg_number` is a soft reference to `users_pis.nsg_number` (no foreign key, ADR-020).
2. **Storage:** local persistent disk under `Form16Storage:RootPath`. The root **is** the form16 folder: `{root}/{assessmentYear}/{nsgNumber}/part-a.pdf|part-b.pdf`, uploads staged in `{root}/_incoming` (same volume, so the final step is a rename). The root must be absolute and outside both `wwwroot` and the application deployment directory (`AppContext.BaseDirectory`), or the service refuses to use it. Windows development: `D:/NSGStorage/Form16` (`appsettings.Development.json`, not published). Ubuntu production: `/var/lib/nsg-mobile/uploads/form16` (committed default). Linux modes: directories `0750`, files `0640`.
3. **Safe names (revised 2026-11-06):** the assessment year must be `yyyy-yy` with consecutive years. There is no approved NSG number format (OQ-032), so no format is imposed: the NSG number must exist in PIS (POST) or in an existing record (PUT), and is only checked for "not blank, at most 30 characters, no control characters" (the PIS envelope). The folder name is never the raw text: `Form16Rules.FolderNameFor` keeps `A-Z a-z 0-9 - _` and escapes every other character as `%XX` per UTF-8 byte (and the first letter of a Windows device name such as `CON`). The mapping is reversible, so distinct NSG numbers never share a folder, and no input can produce a separator, `.`/`..`, or a leading/trailing dot or space. The database stores the NSG number in the spelling held in PIS (not as typed) and the relative path built from the encoded folder.
4. **Safe replacement (file and row stay consistent):** each PDF is streamed to staging and checked (`%PDF-` signature, non-empty, size limit `Form16Storage:MaxPdfSizeBytes`, default 10 MB). Commit moves any existing file aside as a backup, renames the staged file into place, saves the row, then discards the backup. If the row cannot be saved, or the second part fails, every committed file is rolled back (old file restored, new file removed). A validation failure on either part applies neither. One upload at a time per (NSG number, year) inside a process; across instances the unique index prevents duplicate records.
5. **Authorization:** the four admin endpoints use the existing `RequireSalaryManagementAdmin` policy (no new role or policy). Decision confirmed 2026-11-06: any Salary Admin views and manages the Form 16 records of all employees, whoever uploaded them (unlike salary slips, there is no per-uploader scoping); `uploaded_by` records the latest uploader only. The four mobile endpoints use `RequireMobileProfile`; the person is resolved from the token (profile → NSG number) and no mobile endpoint accepts an NSG number or record id. Ownership is the lookup key itself and is re-checked on the returned row. Unavailable, foreign and file-less documents are all 404; storage paths and public URLs are never returned (only relative API routes).
6. **Semantics:** POST creates (201) or updates (200) the supplied parts only and requires the NSG number to exist in PIS; PUT updates supplied parts of an existing record, 404 otherwise, and never creates. Both reject a request with no PDF.

## Consequences / known limits
- Verified on Windows only. Verified 2026-11-06 against an isolated local MySQL 8 test database (`NSG_TEST_MYSQL`, `*_test`): the migration (apply, schema, unique index, rollback, re-apply), every `Form16Repository` query, and JWT/role/ownership behaviour through the real pipeline. **Not verified:** Ubuntu 24.04, MySQL on Linux, and the production database (see OQ-047).
- A hard process crash between the file move and the row save can leave a `.bak` or an orphan file next to the stored one; neither is ever served. Files and `personnel_form16` rows must be backed up and restored together.
- Folder names do not carry the person's name, but the NSG number is in the path on disk.
